# Using Markdown and MDX in Documentation

> Markdown is a text-to-HTML conversion tool for web writers. MDX adds the ability to use JSX components within Markdown documents.

> Markdown allows you to write using an easy-to-read, easy-to-write plain text format, then convert it to structurally valid JSX.

For example, this entire page was created using Markdown!

Below is a quick reference of all the syntax that is supported by MDX.

## Headings

```mdx
# H1
## H2
### H3
#### H4
##### H5
###### H6
```

## Lists

> In this example, leading and trailing spaces are shown with with dots: ⋅⋅⋅

```mdx
1. First ordered list item
2. Another item
   ..- Unordered sub-list
3. Actual numbers don't matter, just that it's a number
   ..1. Ordered sub-list
4. And another item

...You can have properly indented paragraphs within list items. Notice the blank line above, and the leading spaces (at least one, but we'll use three here to also align the raw Markdown).
```

## Links

```mdx
1. To link Inline-style
[I'm an inline-style link](https://www.google.com)

2. To link Reference-style
[I'm a reference-style link][https://www.google.com "Google's Homepage"]

3. To link to API explorer from documentation pages
[API page](../../api/post/v1/apis)

4. To link/reference to another document/markdown
[Charge](../Transactions/Charges.md)

5. To create anchor link within the page. You can place anchor by declaring <a name = "portal" />. Now you can reference this link anywhere within the page by declaring link such as [Dev Portal](#portal)
```

## Tables

Tables aren't part of the core Markdown spec, but they are part of GFM and _Markdown Here_ supports them. They are an easy way of adding tables to your email -- a task that would otherwise require copy-pasting from another application.

```mdx
Colons can be used to align columns.

| Tables        | Are           | Cool  |
| ------------- |:-------------:| -----:|
| col 3 is      | right-aligned | $1600 |
| col 2 is      | centered      |   $12 |
| zebra stripes | are neat      |    $1 |


The outer pipes (|) are optional, and you don't need to make the raw Markdown line up prettily. You can also use inline Markdown.

Markdown | Less | Pretty
--- | --- | ---
*Still* | `renders` | **nicely**
1 | 2 | 3
```

| Markdown | Less      | Pretty     |
| -------- | --------- | ---------- |
| _Still_  | `renders` | **nicely** |
| 1        | 2         | 3          |

## Custom components

You can also use custom components within MDX files. For example, the `Alert` component below is used to display an alert box.

```mdx
<Alert type="warning" message="This is a warning alert!" />

<Alert type="info" message="This is an info alert!" />

<Alert type="error" message="This is an error alert!" />
```

<Alert type="warning" message="This is a warning alert!" />

<Alert type="info" message="This is an info alert!" />

<Alert type="error" message="This is an error alert!" />

All components made available by the [Launch Point library](https://launch-point-ui-storybook-dev-launch-point.apps.dtuscedevstudiolower.centralus.aroapp.io) can be used within MDX files without importing them explicitly.
