# Batch transaction processing

<Tags tags={frontmatter.tags} />

Batch file processing allows a merchant to process multiple transactions in bulk by submitting a file containing all the transactions that need processing via secure FTP *(SFTP)*. Commerce Hub supports a JSON file format that aligns with the [Commerce Hub API specifications](?path=docs/Resources/API-Documents/OpenAPI-Specs.md). Additionally, Commerce Hub supports manual file uploads through [Commerce Control Center's Virtual POS's Quick Key feature](?path=docs/Resources/Guides/Enterprise-Portal/Virtual-Terminal.md).

A secure communication channel is required to submit batch files. To achieve that, we use the SFTP transfer protocol.

## Batch files

Commerce Hub supports [primary *(authorizations)* and secondary *(capture and refund)* transactions](#request-files) in separate batch files. Each batch file can only hold either primary or secondary transactions. Commerce Hub requires a [specific format](#file-structure) and [naming convention](#filename-convention) when submitting a transaction batch file for processing.

Each batch consists of three separate files:

- **Transaction request file**: Contains the transaction requests to be processed by Commerce Hub.
- **Acknowledgement file**: Generated by Commerce Hub to confirm receipt and validation status of the transaction request file.
- **Transaction result file**: Generated by Commerce Hub to provide the processing results of the transactions submitted in the request file.

The batch file service reads the transactions from the request file and processes them for settlement. Commerce Hub validates each transaction for completeness and accuracy to ensure data integrity. Once the validations are passed, the transactions are sent for settlement. An [acknowledgement file and a detailed result file](#result-files) will be sent back to the merchant.

---

### Filename convention

To be accepted for processing, the filename for each batch request file must be unique and must comply with the following format: `<job_name>.<enviroment>.<client_id>_<seq>.<fileType>.<date>.<time>.txt`. The file must be a text *(.txt)* file.

  <AlertIcon />
  <AlertTitle>Note full width alert</AlertTitle>
  <AlertDescription>The angle brackets *(`<` and `>`)* are used here to indicate placeholders and should be replaced with actual values in the filename.</AlertDescription>
</Alert>

  <TabsList>

The following placeholders are required when creating the text file name.

| Placeholder | Description |
| ----- | ----- |
| `job_name` | Sterling File Gateway *(SFG)* assigned value. |
| `environment` | Defines the processing environment as *TEST* or *PROD*. |
| `client_id` | Commerce Hub assigned client identifier for the merchant. |
| `seq` | File submission sequence number for a given date. Four-digit number, left-padded with zeros. |
| `fileType` | Three digit value identifying the file type, left padded with zeros. |
| `date` | File submission date in `YYYYMMDD` format. |
| `time` | File submission 24-hour time in `HHMMSS` format. |

  </TabsContent>
  <TabsContent value="File-types">

Commerce Hub defines the following file types:

| File type | Description | Example filename |
| ----- | ----- | ----- |
| **001** | Capture and refund request file submitted by merchant containing one or more transactions to be processed by Commerce Hub. | `inbound_job.TEST.ClientOne_0001.001.20250528.121052.txt` |
| **002** | Capture and refund acknowledgement file generated by Commerce Hub indicating the receipt of the batch request file. | `outbound_job.TEST.ClientOne_0001.002.20250528.121158.txt` |
| **003** | Capture and refund result file generated by Commerce Hub containing the processing result of the transaction records provided in the batch request file. | `outbound_job.TEST.ClientOne_0001.003.20250528.121538.txt` |

  </TabsContent>
</Tabs>

### File structure

Every line in the file will be a JSON string having two required attributes `type` and `data`. All file types will have one header record, one footer record and one or more transaction detail records. The definition of header and footer records are the same for all the file types.

<Alert type="warning" variant="inline">
  <AlertIcon />
  <AlertTitle>Warning</AlertTitle>
  <AlertDescription>If the file format is not correct, or the file contains invalid values for a given variable then the file will be rejected and none of the transactions will be processed. The [acknowledgement file](?path=docs/Resources/Guides/Batch/Batch-Acknowledgement.md) will provide the status of the validation, including any errors.</AlertDescription>
</Alert>

- **Header record:** The header JSON object is expected to be provided in the first line of the file. This holds the metadata information of the batch request file.
- **Transaction detail record:** The transaction detail record holds the details of the transaction to be processed by Commerce Hub. The required and conditional fields are based on the transaction type being performed. The JSON file format that aligns with the [Commerce Hub API specifications](?path=docs/Resources/API-Documents/OpenAPI-Specs.md).
- **Footer record:** The footer JSON object is expected to be the last line of the file.

#### Batch file example

This example shows a complete batch file containing a header record, two transaction detail records *(one for a capture and one for a refund)*, and a footer record. Each line is a JSON object representing a record in the batch file.

```text
{"type":"H","data":{"fileType":"REQ","submissionId":"e7ca0dc929214316954b9ee8c6240ffb","timestamp":"2025-03-12T14:57:38.564508Z","clientId":"clientOne","version":"v1","environment":"TEST"}} // Header record
{"type":"D","data":{"operationType":"CAPTURE","id":"1","detail":{"merchantDetails":{"merchantId":"100008000003683","terminalId":"10000001"},"referenceTransactionDetails":{"referenceTransactionId":"460d26109b344512f018a887a8e67"}}}} // Transaction detail record
{"type":"F","data":{"submissionId":"e7ca0dc929214316954b9ee8c6240ffb","count":2}} // Footer record
```
