# Version 2.0 — Major Release

> Developer Studio Test SDK 1 is an example of file structure and documentation that tenants can use when setting up the documentation for their SDKs. This example is not based on real-world software and is only presented to inform tenants about the SDK functionality now part of the Developer Studio ecosystem.

> Released: January 10, 2025

## Overview

Version 2.0 introduces streaming transaction events, a redesigned error model, and support for batch operations. The client initialization API has been simplified to reduce boilerplate.

## New Features

| Feature | Description |
| ------- | ----------- |
| Streaming events | Subscribe to real-time transaction status changes via server-sent events |
| Batch charges | Submit up to 1,000 charges in a single API call with async processing |
| Idempotency keys | Built-in idempotency key generation to prevent duplicate charges |
| Multi-currency | Process charges in 135+ currencies with automatic conversion rates |
| Staging environment | New pre-production environment for integration testing |

## Breaking Changes

### 1. Client Initialization

The constructor now accepts a single configuration object instead of positional arguments.

**Before (v1.x):**

```javascript
const client = new DevStudioPayments('your-api-key', 'sandbox');
```

**After (v2.0):**

```javascript
const client = new DevStudioPayments({
  apiKey: 'your-api-key',
  environment: 'sandbox'
});
```

### 2. Error Handling

All SDK errors now extend a base `DevStudioError` class. The `code` property has been replaced with structured error types.

**Before (v1.x):**

```javascript
catch (error) {
  if (error.code === 'NOT_FOUND') { ... }
}
```

**After (v2.0):**

```javascript
import { NotFoundError } from '@devstudio/payments-sdk';

catch (error) {
  if (error instanceof NotFoundError) { ... }
}
```

### 3. Response Envelope

List endpoints no longer wrap results in a `results` array. The array is now under `data`.

**Before (v1.x):**

```javascript
const { results, total } = await client.transactions.list();
```

**After (v2.0):**

```javascript
const { data, hasMore, nextCursor } = await client.transactions.list();
```

Replace string-based error code checks with `instanceof` checks:

```javascript
import {
  DevStudioError,
  NotFoundError,
  ValidationError,
  RateLimitError,
  AuthenticationError
} from '@devstudio/payments-sdk';

try {
  await client.charges.create({ ... });
} catch (error) {
  if (error instanceof ValidationError) {
    // Handle invalid input
  } else if (error instanceof AuthenticationError) {
    // Handle auth failure
  } else if (error instanceof DevStudioError) {
    // Handle other SDK errors
  }
}
```
